Accessibility & keyboard

Accessibility is not an option of one renderer: it is described once, in the core state machine (roles, ARIA attributes, accepted gestures), then verified on every renderer by the conformance bench.

Principles

  • Native elements first: a switch, a checkbox, a toggle button are real <button>s; a field wraps a real <input> of the application.
  • A name for every control: the visible label (<label for>, aria-labelledby), otherwise aria-label. An icon without a label is decorative.
  • One tab stop per group (radios, segmented): arrow keys move focus inside (“roving tabindex”), wrapping, skipping disabled options.
  • Disabled ≠ read-only: disabled leaves the tab order (native disabled); read-only stays reachable and readable, but refuses gestures.
  • Right to left: styles written as start / end; slider and rating mirror (scenarios run in rtl).
  • Reduced motion and visible focus: base.css from @poadio/ui-core, shared by every renderer.
  • Assistive texts are translated: “Close”, “Increase”, “Show password”… come from the catalogue, never hard-coded.

The conformance bench

A scenario describes gestures (click, key, typing, pointer, writing direction) and expectations on the DOM (attribute, accessible name, focus, value, emitted events). Each renderer provides an adapter; the same scenario runs on angular, react, vue, elements. The table below is extracted from the scenarios at build time.
