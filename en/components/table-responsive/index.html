What it is for

responsive="scroll" (default): the table scrolls horizontally, with frozen columns if needed. priority: each column has a priority from 1 (never hidden) to 5 (hidden first); below the thresholds (priorityBreakpoints, default 1100 / 900 / 720 / 560 px for 5 / 4 / 3 / 2), it disappears and the detail button shows it (showHiddenInExpansion). stack: below stackAt (640 px), each row becomes a card where each value carries its column label; a card template can replace this rendering, and the bar’s tools move behind a “Filters” button. The width is the container’s, not the screen’s: a table in a narrow panel adapts too.

Accessibility

  • With cards, the structure stays a table (or a grid with selection): rows, aria-rowindex, aria-selected and keyboard are unchanged; each value’s visible label comes from the header (data-l).

What it is for

To keep in view what names the row when columns overflow. A column is frozen with sticky="left" or "right"; stickyFirstColumn freezes the first one; selection and detail columns follow the first column, row actions stay on the right (stickyActions, default yes). The application can pin or unpin a column at run time (pinnedColumns, takes precedence; null unpins). Offsets come from measured widths: nothing to compute. Few frozen columns: each one shrinks the scrolling area.

What it is for

For columns whose content varies (long names, descriptions): users give room to what they read. resizableColumns puts a handle at the edge of every header (a column opts out with resizable: false, or asks for one alone with resizable: true). Dragging the handle changes the width; a double-click fits it to the content (header and the first 200 displayed rows). From the keyboard, the handle is a separator: ← → by 8 px (Shift: 40), Home and End go to the minWidth / maxWidth limits, Enter fits the content. The table switches to a fixed layout: requested widths are kept; leave one column without a width (a description, say): it takes the remaining room; if they all have one, an empty filler column (hidden from screen readers) takes it. Either way, each column keeps exactly its width and the handle follows the pointer to the pixel (“Row numbers, grouped headers, density” page). Chosen widths live in columnWidths ({ [column id]: px }): keep them with onColumnResize (React), v-model:column-widths (Vue), the columnWidths property (web component) or getColumnWidths() (Angular) to find them again on the next visit. For widths users must not change, give columns a width without a handle.

Accessibility

  • The handle is a focusable separator (“window splitter” pattern: role="separator", aria-orientation="vertical", aria-valuenow / aria-valuemin / aria-valuemax in pixels), named “Resize column Service” and described by the keyboard help (aria-describedby).

  • Right to left, the handle sits at the left edge of the header and the arrows follow that direction.
