Field

Wraps an input control: label, hint, error, required or optional mention. The control stays a native <input>, which the field links to its label and its message.

  • Angular
  • Next.js
  • React
  • Vue
  • Vanilla

Demo

Rendered by Angular

No optional option in Angular: give the text with optionalText.

import { Component, computed, signal } from '@angular/core';
import { FormsModule } from '@angular/forms';
import { PoadFieldComponent, PoadInputDirective } from '@poadio/ui-angular';

@Component({
  selector: 'app-field-demo',
  imports: [FormsModule, PoadFieldComponent, PoadInputDirective],
  template: `
    <div class="demo-col">
      <poad-field label="Email" hint="We never share it" [error]="emailError()" required>
        <input poadInput type="email" [(ngModel)]="email" placeholder="ada@example.org" />
      </poad-field>
      <poad-field label="Project name" optionalText="(optional)">
        <input poadInput [(ngModel)]="project" />
      </poad-field>
      <poad-field label="API key" hint="Read-only" disabled>
        <input poadInput mono value="pk_live_1234" disabled />
      </poad-field>
    </div>
    <code>email={{ email() }} · project={{ project() }}</code>
  `,
})
export default class FieldDemo {
  readonly email = signal('');
  readonly project = signal('');
  readonly emailError = computed(() => (this.email() && !this.email().includes('@') ? 'Not an email address' : ''));
}
Rendered by React (@poadio/ui-react)

Next.js uses the same package as React: the demo is rendered by @poadio/ui-react. The code shows the App Router integration — a client component ('use client') for state, rendered by a server page.

// app/field-demo.tsx — client component (state, handlers)
'use client';

import { useState } from 'react';
import { PoadField, PoadInput } from '@poadio/ui-react';

export default function FieldDemo() {
  const [email, setEmail] = useState('');
  const [project, setProject] = useState('');
  const error = email && !email.includes('@') ? 'Not an email address' : '';
  return (
    <>
      <div className="demo-col">
        <PoadField label="Email" hint="We never share it" error={error} required>
          <PoadInput type="email" value={email} onChange={(e) => setEmail(e.target.value)} placeholder="ada@example.org" />
        </PoadField>
        <PoadField label="Project name" optional>
          <PoadInput value={project} onChange={(e) => setProject(e.target.value)} />
        </PoadField>
        <PoadField label="API key" hint="Read-only" disabled>
          <PoadInput mono defaultValue="pk_live_1234" disabled />
        </PoadField>
      </div>
      <code>email={email} · project={project}</code>
    </>
  );
}

// app/page.tsx — server component: HTML rendered on the server, hydrated on the client
import FieldDemo from './field-demo';

export default function Page() {
  return <FieldDemo />;
}

Rendered by Vanilla

The control is yours: a native <input>, <textarea> or <select> written inside <poad-field>, which keeps its value, its validation and its place in the <form>.

<script type="module">import '@poadio/ui-elements/define';</script>

<div class="demo-col">
  <poad-field id="email-field" label="Email" hint="We never share it" required>
    <input id="email" type="email" name="email" placeholder="ada@example.org" required>
  </poad-field>
  <poad-field label="Project name" optional>
    <input name="project">
  </poad-field>
  <poad-field label="API key" hint="Read-only" disabled>
    <input value="pk_live_1234" disabled>
  </poad-field>
</div>
<code id="email-out">email=</code>

<script type="module">
  const field = document.querySelector('#email-field');
  document.querySelector('#email').addEventListener('input', (e) => {
    const email = e.target.value;
    field.error = email && !email.includes('@') ? 'Not an email address' : '';
    document.querySelector('#email-out').textContent = `email=${email}`;
  });
</script>

What it is for

For every form field. The error replaces the hint while it is there; only show it after a first attempt by the user.

Accessibility

  • The <label for> names the control (the field sets an id if it has none).
  • The control is described (aria-describedby) by the hint, then by the error that replaces it; with neither, nothing describes it.
  • In error: aria-invalid="true" on the control, role="alert" on the message.

Verified by the conformance bench — These scenarios are played, identically, on every declared renderer (angular, react, vue, elements) on every push:

  • field/label-hint-error

Theme tokens

--poad-* tokens read by the @poadio/ui-core/field.css, @poadio/ui-core/base.css stylesheet of @poadio/ui-core. Redefining them (globally or on a container) is enough to theme the component, on every framework at once.
