Application shell

<poad-app-shell>

The layout of an application: top bar, menu on the left, content, bottom bar. The shell does not scroll, only the content does: the bars stay in place because they cannot move.

What it is for

Once per application, around everything. It composes the menubar (top zone), the navigation drawer (menu) and the bottom navigation (bottom zone), without owning any of them: below the mobile breakpoint (md, or compactAt in px), it stops reserving a column for the menu, and openNav() signals the request (navRequested) — opening the drawer is up to you. It measures its zones and publishes --poad-shell-top, --poad-shell-bottom and --poad-shell-nav: a toast or a floating button positions itself there without importing anything. Remember viewport-fit=cover in the viewport meta tag, otherwise safe areas are 0 on iOS.

Keyboard

KeyEffect
TabGoes through the top bar, the menu, the content then the bottom bar, in document order.

Accessibility

  • The shell adds no role: landmarks come from what it contains (menubar menubar, drawer navigation, bottom bar navigation, your <main>).
  • The document does not scroll: only the content does (overscroll-behavior: contain), the bars stay reachable without scrolling back.
  • Safe areas: the top bar paints its own (padding-top: env(safe-area-inset-top) on the bar, not on the shell), the modal drawer and the bottom bar reserve theirs.

How to change

In the application’s global stylesheet, after the @poadio/ui-core sheets: on :root for the whole application, or on a container for one area only. A floating layer (menu, list, dialog) may be rendered outside its container: for it, prefer :root.

src/styles.css
/* The whole application */
:root {
  --poad-fg: #0f172a;            /* Main text */
  --poad-font-size: 0.875rem;    /* Base text size */
}

/* In dark theme only */
.theme-dark {
  --poad-fg: #f8fafc;            /* Main text */
}

/* One area only */
.checkout {
  --poad-font-size: 1rem;        /* Base text size */
}
