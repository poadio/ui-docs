What it is for

To write a document made of blocks (documentation, illustrated report); the block view reads it back. Editor.js and its extensions are OPTIONAL dependencies (npm i @editorjs/editorjs @editorjs/header @editorjs/underline @editorjs/delimiter @editorjs/list @calumk/editorjs-codecup editorjs-alert), loaded when the first editor mounts (never during server rendering), once for the page, from the application’s bundle — never a CDN; when missing, the editor says which one to install; without @editorjs/list alone, it works without offering lists. The library’s tools (alignment, YouTube, image, link) and the interface dictionary come from the message catalogue. For short formatted text, prefer rich text.

Keyboard

KeyEffect
/In an empty block: opens the block menu (Editor.js) — arrows to choose, Enter to insert, Escape to close; typing filters the list.
Control /Current block’s options (⌘/ on Mac): alignment, move up, move down, delete — arrows and Enter.
TabFrom one block to the next (Shift+Tab: backwards); from the last block, leaves the editor.
EnterNew block below the caret; in an open menu: picks the item.
← →On an image’s width handle (a role="slider"): ±5 %; Home / End: 15 % / 100 %.

Accessibility

  • A role="group" area named by ariaLabel (or “Block editor”), the keyboard hint (“/”, Ctrl+/, Tab) linked by aria-describedby. Loading announced, a failure as role="alert" with “Retry”.
  • Library tools: named buttons and fields (caption, YouTube address, crop, change image), keyboard width handle, aria-hidden icons.
  • Editor.js limits, honestly: blocks are editable areas with no name or role of their own; the “+” buttons and the ⋮⋮ handle are not in the tab order (“/” and Ctrl+/ replace them); dragging blocks exists only with the mouse (Move up / Move down with the keyboard); opening menus is not announced by screen readers.

What it is for

To display what the block editor produced (documentation page, report, record): no dependency, the { time, blocks, version } JSON is enough, server rendering included. Headings get unique anchors and the component emits the table of contents (toc). An application-specific block type is shown by a template (Angular poadBlockTemplate, React and web components renderBlock, Vue block-<type> slot). Security: every block goes through ui-core’s render model — inline text is read again by the rich text rules (b i u s code mark marks, a link with a safe href, nothing else), an image is shown only if its address is safe, a video only if it is YouTube (rebuilt address), code stays text, the highlighting supplied by the application (highlight) is cleaned.
