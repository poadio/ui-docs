@Component({
  selector: 'app-table-edit-demo',
  imports: [PoadTableComponent, PoadColumnComponent, PoadSegmentedComponent],
  template: `
    <poad-segmented [(value)]="mode" [options]="modes" ariaLabel="Edit mode" size="sm" />
    <poad-table [value]="services()" dataKey="id" title="Services" [editMode]="editMode()" rowActionsAlwaysVisible (editComplete)="save($event)" (rowEditSave)="saveRow($event)">

  `,

  /** Les trois modes : une cellule, toute la ligne en place, ou la ligne dans une boîte de dialogue. */

  readonly editMode = computed(() => this.mode() as Mode);
  readonly envs = ['recette', 'neo', 'prod'].map((e) => ({ label: e, value: e }));
  readonly services = signal<Service[]>([
    { id: 1, name: 'web-01', env: 'prod', pods: 4, active: true },
    { id: 2, name: 'web-02', env: 'prod', pods: 4, active: true },
    { id: 3, name: 'api', env: 'neo', pods: 2, active: true },
    { id: 4, name: 'worker', env: 'recette', pods: 1, active: false },
    { id: 5, name: 'cron', env: 'recette', pods: 1, active: true },
  ]);
  readonly last = signal('—');
  /** La table ne modifie pas les lignes : l'application écrit la valeur validée. */
  save(e: PoadEditCompleteEvent<Service>): void {
    this.services.set(tableEditApply(this.services(), e.row, { [e.column.field()]: e.value }));
    this.last.set(`${e.column.field()}=${e.value}`);
  }
  /** Modes ligne : seuls les champs changés arrivent. */
  saveRow(e: PoadRowEditEvent<Service>): void {
    this.services.set(tableEditApply(this.services(), e.row, e.changes));
    this.last.set(Object.entries(e.changes).map(([k, v]) => `${k}=${v}`).join(','));
  }
}

What it is for

For quick fixes on data already on screen (number of pods, environment, status). editMode="cell": double-click, Enter or F2 opens the cell editor, Enter commits, Escape cancels, Tab moves to the next editable cell. editMode="row-inline": an Edit button per row opens the whole row, Enter or ✓ saves, Escape or ✕ cancels. Per column: editable, editor (text, number, select, checkbox, date, textarea), editorOptions, constraints required, min / max, minLength / maxLength, and validator for your own rules; an application editor replaces the built-in one (poadEditorTemplate template, editorCell, #editor slot, renderEditor). The table does not change your data: write changes from editComplete / rowEditSave into value (tableEditApply); in Vue, v-model:value does it; the web component writes its own value, unless you cancel the event. No editing in virtual scrolling: the editor and its focus would vanish with their row when it leaves the rendered window, and moving to the next cell would target cells missing from the DOM; to edit a long list, use the paginator. editMode="row": the “Edit row” button opens the row in a library dialog, one field per editable column, validated while typing; “Save” turns on at the first change and sends only the changed fields. It is the right choice for a long form or wide fields (title, size and form columns: the “Row edit dialog” page). The demo switches from one mode to another.

Accessibility

  • In cell mode, the table is a grid (role="grid"); each editable cell is described by the help “Enter or F2 to edit” (aria-describedby).
  • The editor is named after its column header; an invalid value sets aria-invalid and shows its message (role="alert"), taken from the catalogue (table.editRequired, table.editMax…).
  • The “select” editor is the library’s dropdown, never a native list. After commit or cancel, focus always returns to the cell, never to the page.
  • In dialog mode, the dialog is modal (role="dialog", focus trapped), named by its title; its fields are named after the headers and carry aria-invalid and their message on error; once closed, it gives focus back to the row’s button.

What it is for

When a row has too many fields to edit in place, or long ones (a description). editMode="row" adds the “Edit row” button to the actions column; the dialog is the library’s (modal, focus trapped, given back to the button on close). Like the other row actions, this button shows on hover and on focus; rowActionsAlwaysVisible keeps it always visible, as the demo does. Its fields reuse the columns’ editors and constraints (editor, required, min / max, minLength / maxLength, validator): the same as in-table editing. rowEditDialogHeader sets the title, text or a function of the row (default: “Edit”); rowEditDialogSize its size (sm, md, lg); rowEditDialogCols the number of form columns (1 or 2; a text area takes the full width). Only changed fields go into rowEditSave (changes); “Cancel”, Escape or the backdrop emit rowEditCancel. As with the other modes, the table does not change your data (see “Table editing”).

What it is for

When order is data the user decides (steps of a release, priorities of a batch, display order). reorderableRows adds a column of handles; the table does not apply the order itself: put rows from the rowReorder event back into value (in Vue, v-model:value; the web component reorders its own value, unless you cancel rowreorder). dragIndex and dropIndex are positions in value. With the paginator, a row moves within its page; the selection follows the rows. rowDragDisabled excludes rows; rowLabel names a row in the announcements and on its handle (“Smoke tests grabbed, position 5 of 6”, “Move Smoke tests”) instead of its place. No handles when the order is imposed or unknown: under a sort, with groups or a tree, with server data (lazy), in cards, and in virtual scrolling (the grabbed row would leave the rendered window during auto-scroll; for long lists, use the paginator).

Accessibility

  • The handle is a real button, named “Move row 3” and described by the keyboard drag help (aria-describedby).
  • An aria-live region speaks each step: “Row 3 grabbed, position 3 of 6”, “Row 3, position 4 of 6”, “Row 3 dropped…”, “Move cancelled…”. After a keyboard drop, focus returns to the row’s handle, at its new place.
  • With a pointer, the gesture starts only past a threshold (a click stays a click); the area scrolls by itself near its edges; with a finger, the handle does not scroll the page.

What it is for

When pages get in the way (a log, an inventory browsed in one gesture) and rows run into the thousands. virtualScroll turns the window on; give the scrolling area a height (scrollHeight) and rows a fixed height (virtualRowHeight, default 42 px, 34 in dense; cells keep it, on one line). virtualBuffer (default 10) renders a few more rows on each side. The paginator is off; in cards (responsive="stack"), height is no longer fixed and virtual scrolling steps aside. scrollToIndex and scrollToRow bring a row to the top of the view. An expanded detail row is not counted in the height: prefer it without virtual scrolling.

Accessibility

  • aria-rowcount counts every row and each rendered row keeps its absolute aria-rowindex: a screen reader announces “row 50,001 of 100,001”.
