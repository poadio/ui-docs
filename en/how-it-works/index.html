How it is made

The poad component library: one core, native renderers for Angular, React (and Next.js), Vue and web components. The same component behaves identically everywhere — and that is checked on every push.

Architecture

One core: @poadio/ui-core

No framework, no DOM access at import time. For each component: a state machine (state, accepted gestures, ARIA attributes) and a stylesheet (.poad-*). Plus the --poad-* tokens, the icon set and the message catalogue.

Native renderers

Each package only provides the template, in its framework’s own idiom: signals and ControlValueAccessor in Angular, controlled props in React, v-model in Vue, attributes and DOM events for web components. Same DOM, same classes, same ARIA.

A conformance bench

Scenarios (gestures, keyboard, attributes, accessible name) are written once and played on every renderer: 175 scenarios today. A difference between two renderers is a bug in one of them.

The parity rule

A feature ships on every framework, or on none. conformance/ported.json is the source of truth and CI enforces it. This site derives its scope from it: a component appears here only once every renderer ships it.

@poadio/ui-core          tokens · base.css · one sheet per component · state machines · icons · UI_FR / UI_EN
 ├── @poadio/ui-angular   Angular 21+ (standalone components, signals, forms)
 ├── @poadio/ui-react     React 19 · Next.js (server rendering, 'use client')
 ├── @poadio/ui-vue       Vue 3.5+ · Nuxt (v-model, slots, server rendering)
 └── @poadio/ui-elements  web components: HTML, Svelte, Solid, Astro, server-rendered HTML
conformance/              scenarios written once, played on every renderer · ported.json

Reading a component page

Pick your framework at the top of the page — Angular, Next.js, React, Vue or Vanilla (web components): every page follows it, and the choice is remembered (and written in the address, ?fw=vue, to share it). The demo is then rendered by that framework, with the code to copy, then the options under their name in that framework, the events, the keyboard and accessibility (taken from the bench scenarios), the stylesheets to import, the catalogue texts and the theme tokens. Each component’s “Available in …” line switches to another framework in one click.

Renderers declared today: angular, react, vue, elements. A “coming soon” framework shows the code of a renderer that has not shipped yet; its demo will switch on by itself.
