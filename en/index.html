poad UI

The poad component library: one core, native renderers for Angular, React (and Next.js), Vue and web components. The same component behaves identically everywhere — and that is checked on every push.

Architecture

One core: @poadio/ui-core

No framework, no DOM access at import time. For each component: a state machine (state, accepted gestures, ARIA attributes) and a stylesheet (.poad-*). Plus the --poad-* tokens, the icon set and the message catalogue.

Native renderers

Each package only provides the template, in its framework’s own idiom: signals and ControlValueAccessor in Angular, controlled props in React, v-model in Vue, attributes and DOM events for web components. Same DOM, same classes, same ARIA.

A conformance bench

Scenarios (gestures, keyboard, attributes, accessible name) are written once and played on every renderer: 35 scenarios today. A difference between two renderers is a bug in one of them.

The parity rule

A feature ships on every framework, or on none. conformance/ported.json is the source of truth and CI enforces it. This site derives its scope from it: a component appears here only once every renderer ships it.

@poadio/ui-core          tokens · base.css · one sheet per component · state machines · icons · UI_FR / UI_EN
 ├── @poadio/ui-angular   Angular 21+ (standalone components, signals, forms)
 ├── @poadio/ui-react     React 19 · Next.js (server rendering, 'use client')
 ├── @poadio/ui-vue       Vue 3.5+ · Nuxt (v-model, slots, server rendering)
 └── @poadio/ui-elements  web components: HTML, Svelte, Solid, Astro, server-rendered HTML
conformance/              scenarios written once, played on every renderer · ported.json

Reading a component page

Each page shows the component rendered by each framework, in tabs: Angular, Next.js, React, Vue, Vanilla (web components). Your tab choice is remembered. Under each demo, the code to copy. Then the options under their name in each framework, the events, the keyboard and accessibility (taken from the bench scenarios), the catalogue texts and the theme tokens.

Renderers declared today: angular, react, vue, elements. A “coming soon” tab shows the code of a renderer that has not shipped yet; its demo will switch on by itself.

Actions

Button
Triggers an action.Toggle button
A button that keeps a state: pressed or not.Button group
Groups related buttons, attached or as pills.

Fields

Field
Wraps an input control: label, hint, error, required or optional mention.Select
Picks one value from a list of options: WAI-ARIA combobox, type-ahead, filter, clear button, groups, templates.Number
Enters a number: shown formatted for the language (1,234.5), raw text while typing, clamped and rounded on leaving, arrows and buttons by step.Password
A real password input, masked by default, with an eye button to reveal it and, when needed, a strength meter.Input mask
Guides typing into a fixed format (phone, date, company number…): free slots are shown, refused characters do not get in, the caret skips literals.Key filter
Blocks some keystrokes in a free-form input: digits only, hexadecimal, letters… The text stays free in length and shape, only characters are filtered; a paste is cleaned.Rating
A star rating (or any icon of the set), down to half a star if needed; hovering previews, clicking picks.Slider
Picks a value, or a range with two handles, by dragging along a track; stepped, bounded, with optional marks.Inplace editor
Shows a value as text; a click swaps it for its editor (a field, a select…), and Escape or the close button go back to display.Textarea
A native <textarea> dressed like the other controls, which fits in a field (label, hint, error) and can grow with its content (autosize).Color picker
Picks a color: saturation / brightness area, hue and opacity with the pointer or the keyboard, HEX and RGB fields, palette, browser eyedropper.

Choices

Switch
Turns a setting on or off, taking effect immediately.Checkbox
Checks or unchecks an option, with a partial state (aria-checked="mixed") for an “all” box when only some of its children are checked.Radio group
One exclusive choice among a few options shown at once, each with an optional hint.Segmented control
A row of joined buttons to pick a view, a period or a mode: a single choice, or several with multiple.

Feedback

Skeleton
A grey, animated silhouette that holds the place of content being loaded: text, image, avatar.Progress bar
Shows how far a task has gone: a bounded value, or an indeterminate mode when the duration is unknown.Spinner
A spinning circle for a short, unmeasured wait; announced as “Loading” by the catalogue.Meter
Shows a measure within known bounds, split into segments: disk space, quota, budget used.Message
An inline message — information, success, warning, error — with its severity icon and, if needed, a close button.Tooltip
A short text that describes an element on hover and on keyboard focus: show and hide delays, flips against the window edge, Escape hides it.Popover
A floating panel anchored on a target, for short interactive content (filters, settings): flipped against the window edge, closed by an outside press or Escape, optional focus trap, bottom sheet on small screens.

Display

Icon
Draws an icon from the library's named set (the same in every framework), as a stroked SVG that takes the text colour.Badge
A small counter or status dot, placed next to a label or an icon: notifications, pending items.Tag
Qualifies an item with a short word and a colour: status, category, environment.Chip
A compact item the user removes or selects: active filter, recipient, keyword, person.Avatar
Represents a person or an entity: a photo, otherwise initials on a hue derived from the name, otherwise an icon.Avatar group
Stacks overlapping avatars; beyond max, the next ones are summed up by a “+N” avatar.Divider
Separates two areas, horizontally or vertically, with optional text placed at the start, middle or end.
